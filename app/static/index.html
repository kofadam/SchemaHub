How it works

Typical pipeline flow from sample data to validated production payloads.

Pipeline flow
1
Generate
Paste a sample payload in the Generator to auto-infer the schema structure and types.
POST /generate-schema
2
Refine
Open in the Visual Builder to add constraints, required fields, enums, and conditional rules.
/builder
3
Register
Save the schema to the registry once. Get a reusable UUID your pipelines reference by ID.
POST /schemas
4
Validate
Call validate from any pipeline or script. Pass the schema_id — no need to repeat the schema.
POST /validate
Help

Quick reference — when to use each tool and what each format supports.

⚡ When to use the Generator Recommended first step

  • You have an existing payload and want a schema quickly
  • Starting from scratch — generate a base, then refine in Builder
  • JSON and CSV only — XML schemas must be written manually as XSD
  • The generator marks all fields as required if they have no empty values in the sample
  • Always review the generated schema before using in production

🏗 When to use the Builder Full control

  • Adding constraints the generator can't infer: regex patterns, min/max, enums
  • Building conditional validation: if role = admin then permissions required
  • Nested objects with their own required/optional fields
  • Click Open in Visual Builder from the Generator to import and refine
  • Use ↑ Register in the preview panel to save directly to the registry

📡 Calling the API from pipelines Automation

  • Use schema_id in validate calls — register once, reference forever
  • Or send schema_inline directly if the schema is stored in your repo
  • data must be a string — serialize your payload before sending
  • TLS uses internal CA — pass -k in curl for testing, import CA for production
  • HTTP 429 = rate limit hit, HTTP 413 = payload too large

📐 Supported formats 3 formats

  • JSON — validates against JSON Schema 2020-12. Supports all standard keywords.
  • CSV — validates against Frictionless Table Schema. Type checking, required fields, min/max constraints.
  • XML — validates against XSD. Schema must be provided manually — auto-generation not supported.
  • The registry stores schemas for all three formats. Use format field to specify.
